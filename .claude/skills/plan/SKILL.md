# plan — 実装前の要件・仕様の壁打ち

実装に入る前に、作るものの輪郭をユーザーと一緒に固めるためのスキル。コードは書かない。

## 前提

ProgPath は「2〜3 人で 1 台を囲む学校授業」を基本単位とする小学生向けアプリ。仕様検討時は常にこの利用前提を判断基準にする（`CLAUDE.md` 参照）。

## 手順

1. **目的の確認**: 何を・なぜ作る/変えるのかをユーザーに確認する。曖昧なら質問で埋める。
2. **要件の整理**: 機能要件・非機能要件・対象ユーザー（授業／2〜3人グループ）・成功条件を箇条書きで言語化する。
3. **制約の確認**: 技術スタック（TS/React/R3F/Tauri/TanStack DB/Zustand）と FSD アーキテクチャ上、どのレイヤー・スライスに属するかを検討する。
4. **設計選択肢の提示**: 取りうる方針が複数ある場合は、トレードオフ付きで提示し、推奨を 1 つ示す。
5. **合意**: ユーザーと仕様を確定する。未確定点が残るなら明示して持ち越す。
6. **Issue 化**: 作業として追跡すべきなら `issue` スキルを起動し、確定した要件・受け入れ条件を Issue にする。

## アウトプット

- 確定した要件・仕様・スコープ外事項のまとめ
- （必要なら）Issue 化した番号と URL

## 注意

- このスキルでは実装・ファイル編集をしない。設計と合意形成に徹する。
- 大きめ・複数ファイルにまたがる変更が見込まれる場合は、Claude Code の plan mode（EnterPlanMode）と併用する。
