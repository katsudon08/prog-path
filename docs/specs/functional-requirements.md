# 機能要件 (Functional Requirements)

本ドキュメントでは、アプリケーションが提供するべき具体的な機能とその動作について定義します。

## 1. コア機能
### 1.1. QRスキャンとプレイ画面のフロー
プレイ画面における基本フローは以下の通りとする。
1. ホーム画面に存在する迷路一覧から遊ぶ迷路を選択する。
2. 選択した迷路データがセットされ、プレイ画面（Play）に遷移する。
3. デバイスのカメラにより「コマンドのQRコードカード」を1枚ずつ連続して読み込み、コマンドツリーを構築していく。
4. ツリー構築完了後、「スタートボタン」を押すことでシミュレーションアニメーションが開始される。
5. ツリー上のすべてのコマンドを実行完了（またはエラーで停止）後、カメラ映像にオーバーレイする形で結果（成功・失敗）をフィードバックする。

- 迷路のQRコード（プレフィックス `M:`）を読み取った場合は迷路データとして取り込む。
- コマンドデータは `forward`, `right`, `left`, `if`, `loop` など固定文字列との一致で識別される。
- カメラへのアクセス権限がない場合は、手動入力できるフォールバックを提供する。

### 1.2. コマンドブロックの仕様と実行ロジック
本アプリケーションで実行可能な具体的なコマンド一覧は以下の通りとする。
1. **動作コマンド**:
   - `forward` (前へ1マス進む)
   - `right` (その場で右へ90度向きを変える)
   - `left` (その場で左へ90度向きを変える)
2. **制御コマンド (ネスト可能)**:
   - `loop`: **2回読み込むことで「ループの開始」と「ループの終了」を示す。** 作成されたループの内側（ネスト内）をUI上で選択し、さらにコマンドを読み込むことで多重ネストも可能。ループ回数はUI上の入力欄で「1〜10回」の範囲で変更できる。
   - `if`: `loop` と同様に、**2回読み込むことで「ifブロックの開始」と「終了」を示す。** また、1回目の読み込み直後にモーダル画面が出現し、「どのマスがロボットの前に存在した場合に処理を実行するか（例：前が壁なら等）」の条件を選択・決定させる。

これらのコマンド群は、入れ子構造を含め実行順序を維持する形でUI上に表示される。ユーザーは読み込んだ階層的なコマンド列を視覚的に確認でき、必要に応じて一部の削除やクリアを行える。

### 1.3. 3Dシミュレーションとエラーハンドリング
- 初期配置：ロボットは必ず「スタートマス」に、「南向き」で配置されてシミュレーションを開始する。
- 実行状態（再生、リセット）をユーザーが制御できるUIを提供する。
- **厳密なエラー仕様**:
  - ロボットの進行方向に「壁」が存在する状態で前進コマンドが実行された場合、**ロボットは動かずにその場でエラー**となり、シミュレーションを強制停止（失敗）する。
  - 進行方向の目の前が「迷路外（場外）」の場合も同様に、**動かずにその場でエラー**となり強制停止する。
  - 全てのコマンドを終えても「ゴール」マスに到達していない場合は失敗扱いとする。

### 1.4. オリジナル迷路の作成とシェア（エディタ機能）
- ユーザーは専用のエディタ画面上で、オリジナルの迷路を作成できる。
- **エディタの制限（バリデーション）**:
  - サイズ上限：7×7マス、最大3階層。
  - 必須マス：スタート地点とゴール地点は**必ず各1つずつ**配置しなければならない（2つ以上は不可）。
  - マスの種類：床、壁、開始、ゴール、カギ、テレポート（上昇・下降）の6種類。
  - テレポート仕様：同じXY座標のまま、上下の階層間を移動する。移動先（着地マス）の配置可能タイルは「床・スタート・ゴール・カギ」の4種類に限られる（移動先が壁などの場合は設置不可）。
- 作成完了後、内部で迷路データが圧縮・シリアライズ（`M:` プレフィックス付与）され、シェア用のQRコードとして画面に表示される。

## 2. PWAおよびシステム機能
### 2.1. オフライン動作 (PWA)
- 初回アクセス以降は、ネットワーク接続がない環境でも全コア機能（QR読み取り、シミュレーション実行）が完全に動作する。
- デバイスのホーム画面へのインストール（Add to Home Screen）をサポートする。

### 2.2. データ永続化
- Dexie.js (IndexedDB) を利用し、読み込んだ迷路データや直近のシミュレーション履歴をローカルに保存し、次回起動時に復元する。
