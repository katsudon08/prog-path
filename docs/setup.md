## このドキュメントの概要

このリポジトリで開発を始めるまでの手順です。用意するものは **Node** と **pnpm** の2つだけです。

Node はバージョンが違うと動かないパッケージがあるため、リポジトリが決めた1つの値に全員で揃えます。
その値は `.node-version` に書いてあり、これを手元で読んでくれるのが **fnm** です。
fnm は「プロジェクトごとに Node のバージョンを切り替えるツール」で、
`cd` でフォルダに入った瞬間にそのフォルダの `.node-version` を読んで切り替えます。
グローバルに入れた Node をそのまま使うのをやめるのは、人によってバージョンが違い、
手元では動くのに CI では落ちる (またはその逆) という食い違いが起きるためです。

pnpm は npm の代わりに使うパッケージマネージャーです。
バージョンは `package.json` の `packageManager` に書いてあり、
Node に同梱されている **corepack** がその値を読んで用意します。
そのため pnpm 自体をインストールする手順はありません。

CI 側で同じ値をどう読んでいるかは、[CI設定のドキュメント](ci.md)の「実行環境の固定」を参照してください。

## 対象読者

このリポジトリで初めて開発環境を作るエンジニアです。
fnm も corepack も知らない前提で書いています。

## 手順

上から順に実行します。
手順1と2はマシンに1回だけ、手順3以降はリポジトリを手元に持ってきたときに実行します。

### 1. fnm を入れる

macOS の場合は Homebrew で入れます。

```bash
brew install fnm
```

Windows の場合は winget で入れます。

```powershell
winget install Schniz.fnm
```

### 2. シェルに設定を書く

fnm は入れただけでは効きません。
シェルが起動するたびに fnm を読み込ませる必要があるため、シェルの設定ファイルに1行足します。

zsh の場合は `~/.zshrc` に次を書きます。

```bash
eval "$(fnm env --use-on-cd --shell zsh)"
```

PowerShell の場合は `$PROFILE` に次を書きます。

```powershell
fnm env --use-on-cd --shell powershell | Out-String | Invoke-Expression
```

`--use-on-cd` は「`cd` でフォルダに入ったときに `.node-version` を読んで自動で切り替える」オプションです。
これを付けておけば、プロジェクトを移動するたびに手でバージョンを指定する必要がなくなります。

書き足したら、ターミナルを開き直して設定を反映させてください。

### 3. Node を入れる

リポジトリのルートで実行します。

```bash
fnm install
```

バージョンの指定は要りません。`.node-version` を読み、そこに書かれたバージョン (現在は 24.14.1) を入れます。

入れただけでは今開いているターミナルは切り替わらないため、続けて次を実行します。

```bash
fnm use
```

こちらも `.node-version` を読み、その場で使う Node を切り替えます。
手順2の `--use-on-cd` は `cd` でフォルダに入った瞬間に働く設定なので、
すでにリポジトリの中に居る状態では発火しません。そのため最初の1回は `fnm use` で明示的に切り替えます。
`node -v` が `.node-version` と同じ値を返せば切り替わっています。

### 4. corepack を有効にする

```bash
corepack enable
```

これで `pnpm` コマンドが使えるようになります。

**このコマンドは Node のバージョンごとに1回必要です。**
fnm は Node のバージョンごとに別々の場所へコマンドを置くため、
別のバージョンで実行済みでも、新しく入れたバージョンには引き継がれません。
`pnpm` が見つからないと言われたら、まずこのコマンドを実行し忘れていないか確認してください。

### 5. 依存を入れる

```bash
pnpm install
```

`pnpm-lock.yaml` に書かれたとおりのパッケージが入ります。
あわせて `prepare` が走り、コミット前とプッシュ前の検査を行う Git フックも設置されます。

初回は corepack が pnpm 本体を取りに行くため、
`Corepack is about to download ...` というダウンロードの確認が出ます。`Y` を入力して進めてください。
