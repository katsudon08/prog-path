# ビルド＆テスト手順（Build & Test）

継続的な品質保証と開発効率を引き上げるための手順およびテスト環境の指針です。

## 開発と各種スクリプト
- `npm run dev`: ローカル開発サーバーを起動します（HMR対応）。
- `npm run build`: プロダクション向けの最適化されたビルドを生成します（Vite使用）。
- `npm run preview`: 生成されたビルドファイルをローカルサーバーで提供し、本番同等の動作確認を行います。
- `npm check`: 全体の静的解析・型チェック・フォーマットを一括で走らせるエイリアス（可能であれば設定推奨）。個別の実行は `tsc --noEmit`, `npm run lint`, `npm run format` を使用します。

## テスト戦略（TDD推奨とTesting Trophy）
高い品質を担保するため、Test-Driven Development (TDD) のアプローチを推奨します。また、Kent C. Doddsの提唱する **Testing Trophy（テスティングトロフィー）** の考え方をベースとします。
- **Integration（統合テスト）を最重要視**: 個々の関数のテストよりも、「いくつかのコンポーネントが組み合わさって、ユーザーの目的（QRを読んで、ボタンを押してアニメーションが動く）を達成できるか」の統合テストの割合を全体で一番多く構成します。React Testing Libraryを活用してください。
- **Unit（単体テスト）**: 純粋なロジック層（`shared/lib`配下のアルゴリズムやバリデーション）は Vite + Vitest にて、エッジケースを網羅するユニットテストを実施します（実行: `npm run test`）。
- **E2E（エンドツーエンド）テスト**: Playwright を用いてブラウザ全体での結合動作をテストします。カメラのモックやデータベースのMockingを使用しながら、クリティカルパス（スキャンからゴール到達まで）を定期的に確認します。
- モック化（Mocking）については、コンポーネントのテストにおいては過度に行わず、外部システム（カメラAPIの `navigator.mediaDevices` など）や重いモジュールに限定してください。

## UIコンポーネント開発 (Storybook)
- 独立したUIコンポーネント（特に `shared/ui` や `entities` などの汎用的な画面要素）の開発およびカタログ化には Storybook を使用します（`npm run storybook`）。
- コントロール（Controls）機能を使用して、様々なpropsでの描画分岐や状態（Disabled, Loadingなど）をブラウザ上でシミュレーションしながら開発を進めてください。

## CI/CD連携（予定）
- GitHub ActionsなどのCIパイプラインにおいて、Pull Requestを作成した段階で静的解析、型チェック、ユニットテストが全てパスすることをマージの条件とします。
