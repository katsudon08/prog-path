# セキュリティ（Security considerations）

クライアントアプリケーション動作や外部デバイス接続におけるセキュリティおよびエラー処理の指針です。

## カメラへのアクセス管理とプライバシー
- **HTTPSの必須**: QRコード読み取りに必要な `getUserMedia` APIはセキュアコンテキスト（HTTPS、またはlocalhost環境）でのみ動作します。本番環境のデプロイ時はHTTPSが必須です。
- **権限リクエストのタイミング**: アプリケーションロード時にいきなり権限を要求するのではなく、ユーザーが「スキャン開始」などのアクションを起こしたタイミングで権限を要求し、その理由をUIで明示します。
- **エラーハンドリング**: ユーザーが権限を拒否した (`NotAllowedError`) 場合や、デバイスにカメラがない (`NotFoundError`) 場合、適切にフォールバック（例：手動でコマンドを入力するモードへの切り替えやエラーメッセージ表示）し、クラッシュを防ぐGraceful degradationを確実に実装します。

## 外部からの入力のバリデーション (QRコード)
- QRコードから読み取られたデータや文字列は**完全に信頼できないデータ**として扱います。
- コマンドデータや迷路データとしてパースする前に、必ず Zod などのスキーマバリデーションライブラリを用いて安全な型であることを検査（型チェック、文字列の長さ制限、境界値チェック）し、予想外の値をサニタイズ（またはエラーとして破棄）します。
- 悪意のある特大のペイロードがQRコードに仕込まれていた場合を想定し、パース時の文字数上限・コマンド上限を設けます。

## ReactとXSSクロスサイトスクリプティング対策
- Reactは基本仕様としてDOM挿入時に適切に文字列をエスケープするためXSS攻撃に対する耐性が高いですが、QRコードのデータを直接 `dangerouslySetInnerHTML` に渡す実装は**固く禁じます**。

## ローカルデータストレージと機密情報
- Dexie.js (IndexedDB) を使用してデータを永続化しますが、IndexedDBのデータはデベロッパーツール等から閲覧・改ざんが可能なプレーンテキストとして保存されます。
- クレデンシャル、アクセストークン、あるいはユーザーの致命的な個人情報等の保存は行わず、あくまで「アプリケーションのローカル状態（作成した迷路、コマンド履歴）」のみを保存します。
