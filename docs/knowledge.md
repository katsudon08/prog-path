# 知識＆ライブラリ（Knowledge & Library）

プロジェクト特有のドメイン知識や、採用している各種ライブラリの取り扱いに関するベストプラクティスです。

## フロントエンド
- Vite + React + TailwindCSS (PWA)

## データベース・アクセス戦略 (Dexie.js / `ProgPathDB`)
- **Dexie.js を使用**: IndexedDBをラップした Dexie.js を使用して、PWA環境でのオフライン・ローカルデータ永続化を実現します。
- **アンチパターン**: `ProgPathDB`（Dexieクラスの拡張クラス）のインスタンス化をコンポーネントや各ファイル内で直接何度も行うことは、コネクションリークやパフォーマンス低下を招くためアンチパターンです。
- **Singleton インスタンスの活用**: アプリケーション全体でただ1つのデータベース接続を共有するために、常に `shared/api/db.ts` ファイル内で初期化され、そこからエクスポートされた単一の Singleton インスタンス（変数名 `db` ）をインポートして使用してください。
- 非同期トランザクション (`db.transaction()`) を利用し、複数テーブルをまたぐ更新はアトミックに実行されるように設計します。

## シミュレーション・アニメーション関連 (React Three Fiber)
- ロボットの歩行、旋回などの3D描画には React Three Fiber (R3F) と Three.js を活用します。
- **パフォーマンス最適化**: フレームごとの大量のアニメーション更新処理を React の状態（`useState`）で行うと、Reactツリー全体が毎フレーム再レンダリングされ重くなります。したがって、R3Fの `useFrame` フックを使用し、Reactのライフサイクル外でThree.jsの `ref` に直接ミューテーション（`ref.current.position.set(...)`など）を行うことで、60FPSのスムーズなアニメーションを実現します。

## データ構造とシリアライズ方針
QRコードの実用的な印字サイズと読み取り精度の関係上、データ容量は非常に厳しく制限されます（低めの誤り訂正レベルでも数百文字程度）。
- **迷路データ**: マス目のマップデータをそのまま持つのではなく、RLE (Run-Length Encoding) を使ったストリークベースの圧縮を行い、更にバイナリをBase64（あるいはURL Safe Base64）フォーマットにエンコードしてQRコード化します。**このQRコード化の主要な目的は、児童間で自作した迷路のQRを見せ合い、相互に取り込んで遊ぶ（シェアする）ことです。**パース側では逆の手順で2次元配列のマップデータに復元します。
- **コマンドデータ（コマンドツリーモデル）**: "前進" "90度右回転" などの基本コマンドに加え、`loop` や `if` など入れ子構造を持つコマンドが存在するため、単なる文字列配列ではなく `children` に Command 型の配列を持つ再帰的な構造データとして扱われます。フロントエンド側では、読み取ったデータをパースし、ネストを保った階層的な「コマンドスタック」としてモデル化します。

## 状態管理（State Management）
- アプリケーションの複雑なステート（現在走っているコマンド配列、シミュレーションの進行状況、再生/一時停止など）については、Propのバケツリレーを避けるため、コンポーネントツリーの適所（例えば Feature のルート部分）で状態管理ライブラリを用いてグローバル/ローカルを適切に分けて管理します。
