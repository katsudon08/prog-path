# AR迷路アプリ MVP（Minimum Viable Product）設計書

## 1. MVPの目的
アプリの最重要価値である**「QRコード（物理カード）を読み取ってプログラムを構築し、AR（カメラ映像オーバーレイ）上で3Dキャラクターを動かす」**というコア体験が、ターゲットユーザー（小学校高学年）にとって楽しく、かつChromebook等の環境でパフォーマンスの問題なく動作するかを最速で検証する。

---

## 2. MVPスコープ（実装・検証範囲の提案）

初期段階（MVP）では、コア体験の検証を最優先とし、付加機能の開発を後回し（フェーズ2以降）にすることを提案します。

### 🔘 MVPに含める機能（必須検証項目）
1. **カメラオーバーレイ＆3D表示基盤**
   - デバイスの背面（または前面）カメラの映像を全画面で描画。
   - その上にReact Three Fiberで背景透過の3D空間レイヤーを構築。
   - 簡易的な3D迷路（固定マップ1つ）とキャラクター（仮の3Dモデルやプリミティブな形状）の表示。
2. **QRコード読み取り機能（単体読み取り）**
   - 1枚のQRコードをカメラにかざして読み取り、その命令を画面上のUI（フローチャート）に追加する機能。
   - 命令の種類（例：「前へ進む」「右へ向く」「左へ向く」の3種類程度に限定）。
3. **プログラム実行とアニメーション**
   - 構築したフローチャートの命令群を順次実行（Evaluate）するロジック。
   - 実行に合わせて3Dキャラクターが迷路内をグリッド移動するアニメーション。
4. **ゴール判定**
   - キャラクターが迷路のゴール地点に到達したかを判定し、クリア演出を出す。

### 🔘 MVPから外す機能（フェーズ2以降へ先送り）
1. **迷路エディタ機能**（MVPでは固定のプリセット迷路1つを利用）
2. **迷路の保存・管理（一覧）機能**（DBによる永続化）
3. **QRコードの複数枚同時読み取り**
4. **複雑なプログラミング要素**（「繰り返し（ループ）」や「条件分岐（IF）」などはMVPでは除外か、要検討）

## 3. UIレイアウトの方向性

スケッチ風デザインを適用する前提で、画面レイアウトの構成として以下を想定します。

- **画面構成案**:
    - **背景**: 常にカメラデバイスからのリアルタイム映像を全画面表示。
    - **中央/3Dレイヤー**: カメラ映像に重なるように配置された3Dの迷路とキャラクター（MVP段階では仮のキューブを使用し、後にglTFのロボットモデルに差し替え）。
    - **UIレイヤー**: 
        - **フローチャートエリア**: 画面の**右側**に配置。読み取った命令ブロックが上から下へ（あるいは左から右へ）並んでいくエリア。
        - **操作パネル**: 下部または右下の押しやすい位置に「読み取り開始」「プログラム実行」「リセット」ボタンを配置。

---

## 4. データとアセットの仕様（MVP）

### 4.1. QRコードデータ仕様
QRコードに含まれるデータはシンプルな文字列とし、以下の3種類を初期実装対象（MVP）とする。
- `"forward"` : キャラクターが前方に1マス進む
- `"right"` : キャラクターが右に90度回転する（向きを変える）
- `"left"` : キャラクターが左に90度回転する（向きを変える）

### 4.2. 3Dアセット
- **キャラクター**: MVP段階では動きのロジック構築を優先し、仮の3Dモデル（キューブ等）を使用する。（将来的に、作成済みのロボットのglTFモデルをインポートする）
- **迷路**: 10x10程度のグリッドベースの固定マップ（床と壁で構成）をコード上でハードコーディングして配置する。
