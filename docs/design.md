# Design Document

本ドキュメントは、ProgPath における画面設計・機能仕様・内部データ構造の方針をまとめた設計資料である。  
本段階では **実装・技術詳細には踏み込まず、仕様と設計のみを定義する**。

---

## 1. アプリ概要

ProgPath は、小学校高学年の児童を対象とし、

- QRコードカードによる物理的操作
- AR風3D表現
- 2人1組の協力的な試行錯誤

を通して **プログラミング的思考を育てる** Web / デスクトップアプリケーションである。

### 1.1 技術スタック

| レイヤー | 技術 |
| --- | --- |
| フロントエンド | React + TypeScript + Vite |
| デスクトップ | Tauri (Rust) |
| 3Dエンジン | React Three Fiber (@react-three/fiber) |
| データ永続化 | LocalStorage / Tauri FileSystem API |

---

## 2. 画面構成一覧

本アプリは以下の3画面で構成される。

1. ホーム画面
2. 迷路の作成・編集画面
3. 迷路の実行画面

全画面に共通ヘッダーを持つ。

---

## 3. 全画面共通ヘッダー

### 3.1 表示要素

| 要素 | 説明 |
| --- | --- |
| ホームボタン | ホーム画面へ遷移する |
| ページ名 | 現在表示中のページ名を表示 |
| ダウンロードボタン | デスクトップ版アプリをGitHubリリースページからダウンロードする |

### 3.2 振る舞い

- ヘッダーには **迷路読み込み・作成系の操作は含めない**
- ナビゲーションと補助操作に限定する

---

## 4. ホーム画面設計

### 4.1 役割

- 迷路の管理拠点
- 作成・編集・実行の起点
- 迷路データの整理（フォルダ）

### 4.2 レイアウト構成

#### 左側：迷路一覧エリア

- フォルダと迷路を縦一列で表示
- ツリー構造（フォルダ → 迷路）
- フォルダは開閉可能（デフォルト: 閉）
- フォルダ自体は選択不可、選択できるのは迷路のみ
- ドラッグ＆ドロップによる並び替え・移動が可能

##### 上部操作ボタン

| ボタン | 機能 |
| --- | --- |
| 迷路作成 | 迷路作成画面へ遷移 |
| フォルダ作成 | 新規フォルダを追加 |
| 迷路読み込み | カメラを起動し、ポップアップウィンドウにカメラ映像を出し、QRコードを読み取って迷路データをインポート |

#### 右側：迷路プレビューエリア

- 迷路名の表示
- 選択中迷路の3Dプレビュー

##### プレビュー下部の操作ボタン

| ボタン | 機能 |
| --- | --- |
| 編集 | 対象迷路の編集画面へ遷移 |
| 実行 | 対象迷路の実行画面へ遷移 |
| QRコード | 対象迷路をQRコードとして表示 |

### 4.3 フォルダ仕様

- 迷路を整理するための論理単位
- フォルダ名を持つ（クリックで編集可能）
- 空フォルダを作成可能
- フォルダのネストは不可（1階層のみ）
- 並び順はユーザー操作で変更可能

## 5. 迷路作成・編集画面設計

### 5.1 役割

- 迷路の新規作成
- 既存迷路の編集
- 構造・ルールの整合性を担保する

### 5.2 編集可能な要素

| 項目 | 範囲 |
| --- | --- |
| 迷路名 | 任意の文字列 |
| 迷路サイズ | 5×5 ～ 10×10 |
| 階層数 | 1 ～ 5階 |
| 各階層のタイル配置 | 下記タイル種類を参照 |

### 5.3 タイル種類

各マスには以下のいずれか1つを配置できる。

| タイル | 説明 |
| --- | --- |
| 床 (floor) | ロボットが移動可能な通常タイル |
| 壁 (wall) | ロボットが進入不可 |
| 穴 (hole) | 落下で失敗。埋めると床になる |
| カギ (key) | ゴール判定時にすべて取得しているか否かで判定が成功か失敗か変わる |
| テレポート上 (teleport_up) | 1つ上の階層の同じ座標へ移動 |
| テレポート下 (teleport_down) | 1つ下の階層の同じ座標へ移動 |
| スタート (start) | ロボットの開始位置 |
| ゴール (goal) | クリア判定位置 |

### 5.4 初期配置ルール

新規作成時のデフォルト状態:

- 階層数: 1階
- サイズ: 5×5
- 左上マス: スタート
- 右下マス: ゴール
- その他: 床

### 5.5 スタート・ゴールの制約

- スタートとゴールは **全階層を含めて各1つのみ**
- 再配置時: 以前のスタート / ゴールは床に戻る

### 5.6 テレポート仕様

- 同一座標で上下階層を移動
- 利用回数制限なし
- テレポート先に **カギ**、**ゴール** が存在する場合も通常通り判定を行う

### 5.7 保存時バリデーション

以下の場合、保存不可とし **トースト通知** でエラーを表示する。

| エラー条件 | メッセージ例 |
| --- | --- |
| スタートが存在しない | 「スタートをおいてね」 |
| ゴールが存在しない | 「ゴールをおいてね」 |
| スタートまたはゴールが複数 | 「スタート/ゴールは1しかおけないよ」 |
| 複数階層でテレポートが不足 | 「〇階と〇階をつなぐテレポートをおいてね」 |
| 1階のみでテレポートが存在 | 「1階のみの迷路にテレポートは置けないよ」 |
| 存在しない階層へのテレポート | 「テレポート先の〇階は存在しないよ」 |
| テレポート先が壁・穴・テレポート | 「テレポート先には障害物があっておけないよ」 |

### 5.8 画面遷移

- 保存後はホーム画面へ戻る
- 作成・編集画面から直接実行画面へは遷移できない

## 6. 迷路実行画面設計

### 6.1 役割

- QRコードによるコマンド入力とフローチャート構築
- シミュレーション実行とフィードバック

### 6.2 レイアウト構成

#### 左側：カメラオーバーレイ

| 要素 | 位置 | 説明 |
| --- | --- | --- |
| カメラ映像 | 背景 | デバイスカメラの映像 |
| 3D迷路・ロボット | 中央 | AR風に迷路とロボットを表示 |
| 階層テキスト | 3D空間内 | 現在の階層を表示（例: 1F） |
| 前進回数 | 左上 | forwardコマンドの実行回数 |
| ミニマップ | 右上 | ロボットの現在階層のマップ。位置・向きを同期表示 |

#### 右側：コマンドスタック

- フローチャート形式で表示
- コマンドの挿入位置を選択可能
- ループ内部も編集可能

### 6.3 コマンド一覧

| コマンド(QRコード) | 内容 |
| --- | --- |
| forward | 前にすすむ |
| right | 右にまがる |
| left | 左にまがる |
| hole | 穴をうめる |
| loop | ループ |

コマンドのQRコードについては、下記の通りです。

| **前にすすむ** | **右にまがる** | **左にまがる** | **穴をうめる** | **ループ** |
| :--: | :--: | :--: | :--: | :--: |
| ![qr-forward](/docs/images/qr/forward.png) | ![qr-right](/docs/images/qr/right.png) | ![qr-left](/docs/images/qr/left.png) | ![qr-hole](/docs/images/qr/hole.png) | ![qr-loop](/docs/images/qr/loop.png) |

これ以外のQRコードは読み込まないようにします。

### 6.4 ループ仕様

| 項目 | 仕様 |
| --- | --- |
| 開始 | QRコード読み込み1回目 |
| 終了 | QRコード読み込み2回目（2回目を読み込む前に、実行ができないようにする） |
| 繰り返し回数 | 1 ～ 10回 |
| ネスト | 最大2重まで |
| 表示 | 折りたたみで中身の表示/非表示切替可能 |

### 6.5 実行制御

| 操作 | 説明 |
| --- | --- |
| 実行 | スタックされたコマンドを順次実行 |
| リセット | ロボット・迷路状態を初期化 |
| コマンド削除 | 各コマンドの削除ボタンで個別削除 |
| 全コマンド削除 | スタック内の全コマンドをクリア |

#### 実行時の初期化

- ロボット位置: スタート
- ロボット向き: 下向き
- 迷路状態: 埋めた穴・取得したカギをリセット

### 6.6 判定とフィードバック

#### 成功条件

- ゴール到達
- 全カギ取得済み

#### 失敗条件

| 条件 | 説明 |
| --- | --- |
| 壁に衝突 | 進行方向に壁がある状態で forward |
| 穴に落下 | 穴タイルに移動 |
| カギ未取得でゴール | カギが残っている状態でゴール到達 |
| 迷路外移動 | マップ境界の外に移動しようとした |

#### 表示方法

- カメラ映像中央にオーバーレイ表示
- 成功時: 前進回数を表示
- 失敗時: 失敗原因を表示

## 7. データ構造

### 7.1 迷路データ (MazeData)

```typescript
interface MazeData {
    id: string;           // 一意識別子 (UUID)
    name: string;         // 迷路名
    folderId: string | null; // 所属フォルダID (null = ルート直下)
    size: number;         // グリッドサイズ (5-10)
    floors: Floor[];      // 階層データ配列
    createdAt: string;    // 作成日時 (ISO8601)
    updatedAt: string;    // 更新日時 (ISO8601)
}

interface Floor {
    level: number;        // 階層番号 (1-5)
    tiles: TileType[][];  // 2次元配列 [row][col]
}

type TileType = 'floor' | 'wall' | 'hole' | 'key' 
              | 'teleport_up' | 'teleport_down' 
              | 'start' | 'goal';
```

### 7.2 フォルダデータ (FolderData)

```typescript
interface FolderData {
    id: string;       // 一意識別子 (UUID)
    name: string;     // フォルダ名
    order: number;    // 表示順序
}
```

迷路はフォルダの中で、配列順に並びます。

### 7.3 LocalStorage キー

| キー | 内容 |
| --- | --- |
| `progpath_mazes` | 迷路データ配列 (JSON) |
| `progpath_folders` | フォルダデータ配列 (JSON) |
| `progpath_expanded_folders` | 展開中フォルダIDリスト (JSON) |

## 8. UI/UX ガイドライン

### 8.1 デザイン方針

- **プレミアム感**: モダンで洗練されたビジュアル
- **直感的操作**: ドラッグ＆ドロップ、タップ/クリックで完結
- **視覚的フィードバック**: アニメーション、トースト通知による状態伝達

### 8.2 アクセシビリティ

- 十分なコントラスト比
- タッチターゲットの適切なサイズ
- エラー時の明確なメッセージ
- レスポンシブデザインへの対応

---

## 9. 実装に関する注意点

**作成用データと実行時状態を分離する設計とする。**

- 実行中のロボット位置
- 取得済みカギ
- 埋めた穴
- forward回数

上記の内容が以下の通りになります。

- ページを離れたら消える
- リロードしたら消える
- 実行画面内だけの一時状態
