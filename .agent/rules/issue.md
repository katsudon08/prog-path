# Issue Convention

AI がイシューを起票する際のフォーマットとルールを定義します。

---

## タイトルフォーマット

```
[type] subject
```

- `[type]` は角括弧付きで先頭に記載
- subject は簡潔に（60文字以内推奨）
- commit の type と対応させる

**例:**
```
[feat] ユーザープロフィール画像のアップロード機能
[fix] ログイン後にリダイレクトが失敗する
[chore] ESLint を v9 に移行する
[docs] API 認証フローのドキュメント追加
```

---

## Type 一覧

| type | 用途 |
|------|------|
| `feat` | 新機能の要件定義・実装タスク |
| `fix` | バグ報告・修正タスク |
| `refactor` | リファクタリングタスク |
| `docs` | ドキュメント作成・更新 |
| `chore` | 環境整備・依存更新・設定変更 |
| `test` | テスト追加・修正 |
| `spike` | 技術調査・PoC |

---

## テンプレート

### feat（新機能）

```markdown
## 概要
<!-- この機能が解決する課題や目的を1〜2文で -->

## 要件
- [ ] 要件 1
- [ ] 要件 2

## 受け入れ条件（Acceptance Criteria）
- [ ] 〜ができること
- [ ] 〜の場合は〜となること

## 関連
- 仕様書: `docs/`
- 依存 Issue: #
```

---

### fix（バグ）

```markdown
## 概要
<!-- 何が・どう壊れているか -->

## 再現手順
1. 
2. 
3. 

## 期待する動作

## 実際の動作

## 環境
- OS / ブラウザ:
- バージョン:

## 関連
- エラーログ:
- 関連 Issue: #
```

---

### chore / refactor / spike

```markdown
## 目的
<!-- なぜこの作業が必要か -->

## タスク
- [ ] タスク 1
- [ ] タスク 2

## 完了条件

## 関連
```

---

## ラベル運用

| ラベル | 意味 |
|--------|------|
| `type: feat` | 新機能 |
| `type: fix` | バグ修正 |
| `type: chore` | 雑務・環境 |
| `priority: high` | 優先度高 |
| `priority: low` | 優先度低 |
| `status: in-progress` | 作業中 |
| `status: blocked` | ブロック中 |
| `needs: review` | レビュー待ち |

---

## AI への指示テンプレート

```
以下の情報をもとに、issue.md のルールに従って GitHub Issue を起票してください。

## 起票したい内容
[やりたいこと・バグ・調査内容を自由記述]

## type
feat / fix / chore / ... （わからなければ AI が判断）

## 制約
- タイトルは [type] subject 形式で60文字以内
- 対応テンプレートを使用する
- 受け入れ条件は具体的・検証可能な形で書く
- 関連 Issue や仕様書へのリンクがあれば含める
```
