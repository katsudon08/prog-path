# 01-architecture.md: 構造定義ルール

## 概要
ProgPath プロジェクトは Feature-Sliced Design (FSD) アーキテクチャを厳格に順守します。 エージェントはコードの生成、移動、リファクタリングの際、常に以下の階層構造、依存関係、および命名規則を維持してください。

### 1. レイヤー構造と依存関係
以下のレイヤー順序を守り、下位レイヤーが上位レイヤーをインポートすることを厳禁とします。

app: アプリ全体の初期化、Provider、グローバルスタイル、ルーティング。

pages: 各画面の構成。複数の widgets を配置し、レイアウトを定義。

widgets: features と entities を組み合わせた自律的な UI ブロック。

features: ユーザーの行動（Action）。（例：QRコードスキャン、実行指示）

entities: ビジネスドメインのモデル。（例：Robot, Maze, Command）

shared: プロジェクト全体で再利用される基盤。（UI、汎用lib、共通型）


**重要な制約**:

同一レイヤー内の依存禁止: 同じレイヤー内のスライス間（例：entities/robot から entities/maze）の直接参照は禁止です。これが必要な場合は、上位レイヤーで組み合わせるか、共通部分を shared へ抽出してください。

循環参照の禁止: いかなる場合も循環参照を許容しません。


### 2. インポート規約（Public API）
モジュール性を高め、内部構造を隠蔽するために以下のルールを適用します。

Public API の順守: 他のスライスからコードをインポートする際は、必ずスライス直下の index.ts を経由してください。

- ❌ import { RobotModel } from '@/entities/robot/ui/RobotModel'

- ✅ import { RobotModel } from '@/entities/robot'

ワイルドカードの回避: export * from ... は避け、エクスポート対象を明示してください。

### 3. スライス内セグメントの構成
各スライス（例：entities/robot/）は以下の標準セグメントで構成します。ディレクトリ名やファイル名は原則 kebab-case で統一してください。

- ui/: React コンポーネント、スタイル、および 3Dモデル定義・アセット（.glb等）。

- model/: 状態管理（Zustand等）、型定義、ビジネスロジック。

- lib/: そのスライス内でのみ使用されるユーティリティ。

- api/: バックエンド通信、外部APIとのやり取り。

- index.ts: Public API。外部に公開する要素のみを明示的に export する。


### 4. 共通関数の配置（Shared Lib）
ドメインに依存しない計算ロジック等は shared/lib に配置します。

3D数学ロジック: Three.js に関連する汎用的なベクトル処理、座標計算などは shared/lib/math 等に集約してください。

UIコンポーネント: Shadcn/ui のような汎用部品は shared/ui に配置します。

---

エージェントへの指示
提案するコードがどのレイヤーに属すべきか常に判断してください。

既存のファイル構造がこのルール（特にレイヤー間・同一レイヤー内の依存関係）に違反しているのを発見した場合は、即座にリファクタリングを提案してください。

新しいコンポーネントを作成する際は、適切なスライス内に index.ts を作成し、Public API を定義してください。
