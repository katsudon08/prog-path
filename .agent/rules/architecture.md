# 01-architecture.md: 構造定義ルール

## 概要

ProgPathプロジェクトは Feature-Sliced Design (FSD) アーキテクチャを厳格に順守します。
エージェントはコードの生成、移動、リファクタリングの際、常に以下の階層構造と依存関係を維持してください。


### 1. レイヤー構造と依存関係

以下のレイヤー順序を守り、**下位レイヤー（下の方）が上位レイヤー（上の方）をインポートすることを厳禁**とします。
また、同一階層内での循環参照（Circular Dependency）も禁止します。

**app**: アプリケーション全体の初期化、Provider、グローバルスタイル、ルーティング。

**pages**: 各画面の構成。複数のwidgetsを配置し、ページのレイアウトを定義。

**widgets**: features と entities を組み合わせた自律的なUIブロック。

**features**: ユーザーの行動（Action）。（例：QRコードスキャン、実行指示など）

**entities**: ビジネスドメインのモデル。（例：Robot, Maze, Commandなど）

**shared**: プロジェクト全体で再利用される基盤。（UI、汎用lib、共通型）


### 2. インポート規約（Public API）

各スライスの内部構造を隠蔽し、モジュール性を高めるために以下のルールを適用します。

- Public APIの順守: 他のスライスからコードをインポートする際は、必ずスライス直下の `index.ts` を経由してください。

**例**
- ❌ `import { RobotModel } from '@/entities/robot/ui/RobotModel'`
- ✅ `import { RobotModel } from '@/entities/robot'`

- ワイルドカードの回避: `export * from ...` のようなワイルドカードエクスポートは極力避け、エクスポートする対象を明示してください。


### 3. スライス内セグメントの構成

各スライス（例：entities/robot/）は、以下の標準セグメントで構成します。必要に応じて、セグメント内でさらにディレクトリを分けて整理することが可能です。

- `ui/`: Reactコンポーネント（見た目、スタイル）。
- `model/`: 状態管理（Zustand等）、型定義、ビジネスロジック、データ加工。
- `lib/`: そのスライス内でのみ使用されるユーティリティやヘルパー関数。
- `api/`: バックエンド通信、外部APIとのデータやり取り。
- `index.ts`: Public API。外部に公開する要素のみを明示的にexportする。


### 4. 共通関数の配置（Shared Lib）

特定のドメインに依存せず、プロジェクト横断的に使用される計算ロジック等は shared/lib に配置してください。

- 対象: 座標計算、ベクトル演算、純粋関数、共通のデータフォーマッタなど。
- 3D数学: Three.jsに関連する汎用的なベクトル処理などは shared/lib/math 等に集約することを推奨します。


### エージェントへの指示:提案するコードがどのレイヤーに属すべきか常に判断してください。既存のファイル構造がこのルールに違反しているのを発見した場合は、リファクタリングを提案してください。
